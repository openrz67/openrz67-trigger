# Review 2026-09-25: rev 3 source against industry practice

Question asked: is the board "as good as it gets", does it follow reference designs and
good practice? Reviewed with the kicad analyzers, ERC/DRC via kicad-cli, and the Espressif
ESP32-C3 hardware design guidelines, BQ25185 / TPS63031 datasheet layout sections, USB-C and
LiPo practice from memory (no `datasheets/` extraction in the repo). Verdict: electrically
sound and unusually well documented for a hobby board; the gaps below are the distance to a
commercial reference layout, not bugs. Rev 2 works; nothing here is a must-fix.

| Sev | Finding | Disposition |
|---|---|---|
| should | No ESD/TVS on USB-C D+/D−/VBUS/CC | **Accepted.** No room: the 0402 column (R4/R5/R9/R10) sits 0.4 mm from the USB pads and L3 / A1 close the corner above and below. The bottom side is 0.5 mm over the cell's foam and would need two-sided assembly. The C3's USB pins are ±2 kV HBM behind 22 Ω, D± only carry the `debug` build, and VBUS feeds the 20 V-rated BQ25185 IN through 10 µF. Revisit if the USB corner is ever re-laid out (a SOT-23-6 USBLC6-2SC6 in flow-through between the pads and the resistors). |
| should | RF line ~60 Ω (0.5 mm coplanar, 0.127 gap, 1.6 mm FR-4) | **Widened to 0.8 mm** (~52 Ω, hand calculation) from the U.FL pad to C2. The 0.3 mm tail into pin 1 stays: nothing wider fits between 0.5 mm pitch pads, and 7 mm total is ≈ λ/10. |
| should | π-match at the U.FL end, 5 mm from LNA_IN, values untuned | **Accepted.** Moving C1/L1/C2 next to pin 1 means re-laying the strip past C15/C4 and the VCC via. Values are Espressif's placeholders; tuning needs a VNA. Range is verified good in use. |
| should | TPS63031 output cap 5 mm from VOUT (pin 1) | **Fixed.** C24 to (134.15, 95.9), VCC pad 0.8 mm from pin 1, return GND via beside its GND pad. (First cut went next to pin 10 = FB; PR review caught it.) |
| should | BQ25185 IN/SYS/BAT caps 5–10 mm from the pins | **Accepted.** Linear charger: no switching loop, the 10 µF caps remain the transient sink. Moving three 0603 into the U3 corner means moving D3, the ISET/ILIM parts and the STAT2 route. |
| should | Battery input unprotected (reverse polarity, no fuse) | **Fixed for polarity:** Q3 AO3401A P-FET reverse-battery block, `+` on the top silk. No fuse/PTC: the cell's own PCM covers overcurrent, and there is no room for a 1206 PTC in the BAT+ path. README already requires a protected cell. |
| should | Bottom silk said `v2` | **Fixed** (`v3`). |
| should | Schematic note said S2 = GPIO3 | **Fixed.** |
| should | 0.4/0.2 via (JLCPCB surcharge); 0.10 mm annular rings board-wide | **Via fixed** to 0.45/0.25 at (144.605, 104.295). **Rings accepted:** 0.45/0.25 is what rev 1 and rev 2 were fabricated with and is the no-surcharge floor. |
| nice | CHIP_EN RC 11 mm from pin 7 | **Accepted.** The strip below the pad row (GPIO2, 32K_N, VBAT_SENSE) has no 0402 slot. |
| nice | EP paste 100 % with untented vias | **Fixed.** U1 four windows (66 %), U2/U3 85 % area. |
| nice | Still-open README items (VDD_SPI 1 µF, BAT1 `+`, U3 mask dam, power necks, one-via islands) | `+` done, the rest still open. |
| nice | No test points or fiducials | **Accepted.** JLCPCB adds panel fiducials; the bottom faces the cell, the top is full. |
| nice | No fab notes / stackup statement | **Added** to the Ordering section. |

Analyzer output dropped as false positives: "no MPNs" (they are in `Manufacturer Part`),
"U2 VIN has no DC path" (through S3), "VBAT_SENSE no source" (divider tap), "missing pull-up"
on STAT1/STAT2/TS (open-drain / NTC), one-via GND islands (DRC: 0 unconnected), courtyard
edge-distance warnings (copper-to-edge 0.3 passes).

Result: DRC 0 errors / 16 warnings (13 courtyard, 1 silk, 2 text; 2 new courtyard from Q3, 1
gone with C24), ERC 0 errors / 15 warnings (unchanged), schematic parity clean.
